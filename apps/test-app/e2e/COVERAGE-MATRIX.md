# E2E Coverage Matrix — capabilities shipped since 2026-04-12

Baseline: commit `e223a73` (2026-04-12), the last commit that **added** an e2e spec
file (`field-groups.spec.ts`). Head: `c991216` (`integration-202607-a`).

Between those points the suite went from **51 to 52** test cases — one net new
test — while roughly 60 non-merge commits landed in
`packages/canopycms/src/editor` and `src/api` alone.

This matrix enumerates every user-visible capability added in that window and
records whether an e2e test exercises it. Rows marked **deferred** carry a stated
reason; rows marked **added** were filled by workstream C.

Priority rubric: **prod has no shell and no EFS access**. A regression in a path
whose only recovery is "ssh in and fix the filesystem" is unrecoverable in
production, so admin-recovery and multi-editor paths outrank editor polish.

Legend: ✅ covered · 🆕 added by this workstream · ⬜ deferred (reason given)

## What writing these tests found

Three real defects that existing coverage could not have caught, because
nothing exercised these paths:

1. **The test app never called `withCanopy()`** in `next.config.mjs`, so the
   `/assets/:path*` → `/api/canopycms/assets/raw/assets/:path*` rewrite was
   never registered. Every public asset URL the editor renders — MediaLibrary
   thumbnails, ImageField previews, every `/assets/t/{directives}/...`
   transform output — 404'd in the harness. Fixed here; the Playwright
   `webServer` command now builds `canopycms-next` first, since that wrapper
   ships from `dist/`.
2. **Internal groups are unreachable from the Permission Manager**: the "Add
   Groups" picker reads `authPlugin.listGroups()` (external groups only) and
   never `groups.json`, so a group created in Manage Groups can never be
   assigned a permission — even though the authorization check treats internal
   and external groups identically. Filed as
   `permission-manager-internal-groups-unreachable.md`.
3. **A slug-reset race in `EntryCreateModal`**: its slug field resets to
   `'untitled'` from a `useEffect` keyed on `[isOpen, selectedEntryTypeName,
entryTypes]`; when `entryTypes` is not referentially stable, a stray
   re-render between filling the slug and submitting silently reverts it
   (observed ~1 in 8 under suite render pressure, never in isolation).

Two state-leak sources were also closed: `resetWorkspace()` now resets the
task queue (`.canopy-dev/.tasks`) and the asset store (`.canopy-dev/assets`),
neither of which it previously touched. The settings workspace holding
permissions/groups is still not reset — `permissions-groups.spec.ts` clears
its own slice via the API instead.
