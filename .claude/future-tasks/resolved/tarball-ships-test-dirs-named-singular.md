# Published tarballs shipped compiled test/story artifacts (repo-wide)

RESOLVED (2026-08-22, branch `fix/packaging-guard-blind-spots`, epic `adopter-request-intake`) —
widened from the original canopycms-only `__test__`/`__tests__` singular-mismatch finding to a
full repo sweep (verified with real `pnpm pack` tarballs, not just `dist/` listings) after an
independent review reported the same defect class in `canopycms-next` and `canopycms-auth-dev`.

## What was wrong, package by package

- **canopycms**: `tsconfig.build.json` excluded `"**/__tests__/**"` (plural) but two
  directories are named `__test__` (singular) — `src/api/__test__/mock-client.ts` (generated by
  `scripts/generate-client.ts`'s prebuild step) and
  `src/editor/hooks/__test__/test-utils.tsx` — so both compiled straight into `dist/` and
  shipped. Five more loose files, none matching any exclude pattern (not `*.test.ts`, not under
  `src/test-utils/`, not `__test__`/`__tests__`), shipped alongside them:
  `src/config-test.ts`, `src/authorization/test-utils.ts`, `src/paths/test-utils.ts`,
  `src/editor/test-setup.ts` (a vitest `setupFiles` entry, loaded by path, not by import), and
  `src/editor/setup-test-dom.ts` (found to have zero importers anywhere in the repo — likely
  dead code, left as-is since deleting source is out of scope for a packaging fix).
- **canopycms-next**: `tsconfig.build.json` excluded `**/*.test.ts` but not `**/*.test.tsx`, so
  `src/client.test.tsx` shipped as `dist/client.test.{js,d.ts}`.
- **canopycms-auth-dev**: `tsconfig.build.json` had **no** `exclude` at all, so
  `src/dev-plugin.test.ts` shipped as `dist/dev-plugin.test.{js,d.ts}`.

None of these were reachable through any package's `exports` map (Node's exports encapsulation
blocks a deep import to a file not listed there regardless of what physically sits in `dist/`),
so nothing broke for a consumer — this was dead weight and, for `mock-client.d.ts`, internal
API-client shapes exposed in the tarball. One file that looked like the same shape was
deliberately left alone after checking its importers: `canopycms-next/src/test-utils.ts`
compiles to `dist/test-utils.js` but is re-exported from `src/index.ts` itself
(`createMockAuthPlugin`/`createRejectingAuthPlugin`) — a real, intentional part of the `.`
export surface, not a leak.

## What changed

- `packages/canopycms/tsconfig.build.json`: added `"**/__test__/**"` and the five loose paths
  above to `exclude`.
- `packages/canopycms-next/tsconfig.build.json`: added `"**/*.test.tsx"`.
- `packages/canopycms-auth-dev/tsconfig.build.json`: added an `exclude` array (previously
  absent), matching the pattern `canopycms-auth-clerk` already used.
- `scripts/check-esm-imports.mjs` gained a permanent regression guard, `checkNoStrayTestArtifacts`
  — after building, it walks every published package's `dist/` and fails if any file matches a
  test/story filename pattern (`__test__`/`__tests__` directories, `*.test.*`, `*.stories.*`).
  Runs on every `pnpm check:esm` (also wired into CI), so this class cannot silently regress
  again — this is the guard the original filing suggested as "a cheap guard would be a test (or
  an extension of `scripts/check-esm-imports.mjs`)".

Verified with a real `pnpm pack` per package (not `npm pack`, which does not apply
`publishConfig` and would misreport the shape) both before and after: all of the listed files
appeared in the "before" tarball and none in the "after" one, except the legitimate
`canopycms-next` `test-utils.js`/`.d.ts` pair discussed above.
